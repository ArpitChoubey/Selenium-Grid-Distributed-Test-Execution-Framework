# 📌 Project Overview

Modern enterprise applications require testing across multiple browsers, operating systems, and environments while maintaining fast feedback cycles.

This repository demonstrates a **Selenium Grid Distributed Test Execution Framework** that enables scalable, parallel, and distributed execution of Selenium automation tests across multiple browser instances and machines.

The project showcases practical implementation of Selenium Grid execution models including **Standalone**, **Hub-Node**, **Docker-based Grid**, and **Multiple Hub configurations**, helping reduce regression execution time while improving browser coverage.

This repository reflects practical understanding of enterprise automation architecture commonly used in Agile and CI/CD environments.

# 🏗 Selenium Grid Architecture

The framework demonstrates the following Selenium Grid execution models:

### 🟢 Standalone Mode

- Single machine execution

- Local testing

- Beginner-friendly setup

---

### 🟡 Hub–Node Mode

Traditional Selenium Grid architecture where:

- One Hub manages requests

- Multiple Nodes execute tests

- Supports distributed execution

---

### 🔵 Fully Distributed Mode

Enterprise-level Selenium Grid architecture where individual services operate independently for better scalability.

---

### 🟣 Docker Mode

Containerized Selenium Grid execution supporting:

- Docker

- Jenkins

- Cloud Pipelines

- Kubernetes-ready environments

---

# ⚙ Selenium Grid Components

## Selenium Hub

Acts as the central controller.

Responsibilities include:

- Receiving test requests

- Identifying available nodes

- Allocating browser sessions

- Managing execution

---

## Selenium Node

Responsible for actual test execution.

Each Node can host:

- Multiple browser instances

- Different browser versions

- Different operating systems

---

# ⚡ Parallel Execution Formula

Execution Time can be estimated using:

```
Execution Time =
(Number of Tests × Average Test Duration)
------------------------------------------
Number of Parallel Nodes
```

Increasing Grid Nodes significantly reduces overall regression execution time.
